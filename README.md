# 多源数据采集与RPA自动化平台

面向网页抓取、API接入、增量采集、RPA流程编排、数据校验与采集监控的数据工程平台。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm ci
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。

## API调用重试台账

API接入管理下的子台账：失败请求回执按客户端归集生成重试记录，解决"失败请求只留在
服务日志里、运维无法判断哪些接口需要重试"的问题。

- 数据流：API客户端数据 + 失败请求回执 → 解析归集 → `apiclient_retry` 台账。
- 失败请求必须绑定已登记的客户端；同一请求编号只保留首版有效记录，重复登记一律拦住。
- 归属批次以数据版本为准：`v2` 按事件发生时间（反映请求真实发生时段），
  `v1` 旧口径按接收时间（兼容旧数据）；迟到回执各按口径归批，
  一个失败请求始终只对应一个当前重试状态。
- 主要接口（挂在 `/api/apiclient` 下）：
  - `GET /retry`：按客户端、重试状态、来源、数据版本筛选，分页返回台账快照；
  - `GET /retry/summary`：按客户端和批次汇总失败接口，给出待处理清单；
  - `POST /retry/receipts`：登记失败请求回执，同步回写台账并返回待处理清单；
  - `GET /retry/{id}/diff`：事件时间与接收时间两种口径的归属差异；
  - `POST /retry/{id}/actions`：开始重试、重试成功、重试失败、重新排队；
  - `POST /retry/rebuild`：解析现有回执重新归集，重试状态按请求编号保留。
- 相邻业务面：采集报告页通过 `GET /api/report/retry_review`
  同步显示失败接口批次与待核对清单。
